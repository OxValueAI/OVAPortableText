# OVA Portable Text v1.4 协议设计草稿

状态：历史设计记录（Draft 04）。v1.4 已正式冻结，请以 [v1.4 正式协议](v1.4.md) 为准；以下保留当时的提案与决策过程。
日期：2026-09-21。
目标 SDK：OVAPortableText 0.5.0。
目标协议：`report.v1.4`。
基线：[v1.3 正式协议](v1.3.md)。

## 1. 目标与边界

本次更新支持新版报告中的事件时间轴、阶段进度、流程框架、市场层级和数值区间，并增强现有图表的预测、阶段定位、阈值和量表表达能力。

目标是完整表达图表的数据与业务语义，并由升级后的渲染器呈现完整效果。复用 `line` 或 `bar` 不意味着把业务图表简化为普通折线或柱体。

本草稿是对 v1.3 的增量提案，不是完整协议副本。未涉及的顶层结构、文本、表格、编号和引用规则沿用 v1.3。现阶段不修改 `PROTOCOL.md`、SDK 版本号或默认 `schemaVersion`；待合同确认和实现完成后一起升级。

本文示例均为独立构造的通用数据，不嵌入本地报告设计材料、截图或业务样本。`docs/startup_report_example/` 继续保持 Git 忽略。

### 1.1 保留的架构

- 图表数据继续放在 `datasets.charts[]`。
- 正文和 grid 表格单元格继续使用 `_type = "chart"` 与 `chartRef`。
- 数据集 `id` 与正文实例 `id` 保持不同职责。
- 新图型继续复用 registry 的 `id / anchor / label / meta`。
- 新增展示文案使用语言对象，例如 `{"zh": "阶段", "en": "Stage"}`；现有字段类型不作破坏性修改。
- 颜色、字体、线宽、圆角、标签偏移、图例位置和页面排版由渲染器负责。
- `meta` 保留为扩展信息，不用它代替本次应正式定义的业务字段。

## 2. 能力分组与交付范围

| 能力组 | 图表类型／方案 | 本次覆盖 |
| --- | --- | --- |
| 时间与阶段 | 新增 `timeline`、`stage_progress` | 事件时间轴、企业研发和商业化阶段 |
| 流程与关系 | 新增 `flow` | 多输入模型架构、分组风险筛查流程 |
| 层级与规模 | 新增 `funnel` | 市场范围逐层收窄及各层规模 |
| 数值区间 | 新增 `range` | 估值上下限区间；误差棒与中心点连线列为后续候选 |
| 趋势与定位 | 扩展 `line` | 历史／预测、生命周期曲线、技术成熟度曲线 |
| 评估与比较 | 扩展 `bar` | TRL、风险占比、正负敏感性比较 |

另外扩展 `doughnut.centerContent`，表达圆环中心的指标或文字。

为多面板图补充正文 `_type = "figure"` 组合实例，复用 grid 数据集承载内部排布，统一图号和引用；它不是第六种 chartType。

五种现有类型 `pie / doughnut / bar / line / matrix_bubble` 继续有效。新增类型不得改变旧字段的含义。

## 3. 共享约定

### 3.1 局部标识与数据有效性

- 节点、阶段、序列和数据点的 `key` 是所属图表或数组内的局部标识，不加入全局 ID 索引。
- 所有数值必须有限；不接受 NaN 或 Infinity。
- 缺失值不能自动当成零；无可用观测时应省略该观测或使用下文明确的未知值表示。
- 必须存在的集合与允许为空的集合逐图型定义；v1.4 新图型的主体集合至少有一项。
- 引用错误、重复 key、无效范围应产生可定位到字段路径的校验错误。

以上是新字段与新图型的规则；不得据此在 v1.3 读取路径中追加破坏性校验。使用 v1.4 新能力时应用相应的附加约束。

新增必填 key 必须是非空且非纯空白的字符串；大小写敏感，不自动 trim 或改写。新增必填语言对象必须至少包含一个非空文本；可选字段未提供时应省略，不用 null、空字符串或空对象代替合法值。可选数组允许 `[]`。旧字段的既有空值规则不在此处重定义。

### 3.2 数据性质

拟为 `line`、`bar`、`range` 的序列及其观测新增可选 `dataRole`：

`observed | estimated | forecast`

分别表示观测值、估算值、预测值。观测上的设置覆盖序列设置；全部省略表示未声明，不自动推断为真实观测。

对 line，序列 dataRole 同时描述连接线段，点上的覆盖只描述该点，不改变相邻线段。历史／预测相接必须拆成两个序列；允许复用相同的边界坐标以保持连接，预测序列的起始观测可显式标记为 observed。预测序列不得在内部混入 observed 点；该情况应拆分序列。不同序列之间不自动连线，不通过年份标签后缀猜测是否预测。

line 中只要任一点声明 dataRole，该序列也必须声明 dataRole，避免点都已分类但线段身份未知。点的有效 role 应与序列相同，唯一例外是 forecast 序列的第一个点允许 observed 或 estimated，以连接历史边界；其他身份切换必须拆分序列。bar/range 没有点间线段，仍允许各观测覆盖序列 role。

另在 line、bar、range 数据集上增加可选 `dataBasis = evidence_based | illustrative`，表示整张图的数据基础。省略表示未声明，evidence_based 是作者声明而非系统认证；它与时间／估算角色是两个维度，不互相覆盖。初版不允许一张图混用真实数值和虚构示意数值；应拆成独立数据集后组合。

因此，示意的市场趋势可以同时声明 dataBasis=illustrative、历史段 dataRole=observed、未来段 dataRole=forecast；其中 observed 仅表示示意场景里的历史观测角色，不得呈现为真实市场数据。定性 S 曲线只声明 dataBasis=illustrative 即可，无需硬套 observed/forecast。所有带 illustrative 的图必须展示可见的“示意／非实测”提示，点、标记和文字不得覆盖该身份；定性评估证据可写入 marker.description。

Draft 02 的 dataRole=illustrative 不再作为候选值，示例同步改用 dataBasis，避免把“示意”与“预测”设计成互斥选项。

### 3.3 坐标轴量表

在原 `ChartAxis` 上拟增加以下可选字段，仅在对应图型支持的连续数值轴上使用：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `domain` | `{min: number, max: number}` | 有业务含义的有效范围，例如 TRL 1–9 |
| `ticks` | `{value: number, label: languageObject}[]` | 有业务含义的等级／阶段标签，不是像素刻度设置 |

`min < max`；ticks 按 value 严格递增。ticks 可以独立于 domain 存在；有 domain 时必须在其范围内。domain 是观测的业务有效范围，不是 viewport 或裁剪指令，不能为了放大差异而修改。

普通 grouped bar、line 和 range 的观测必须在 domain 内；range 的两端都要检查。未归一化 stacked bar 的 domain 约束正负累计端点，而非单个段值；零基线可以在 domain 外。参考线、bands 和 ticks 在声明 domain 时也必须位于其内。柱体从零起算，渲染范围包含零基线与 domain，不能把 TRL 1 当作柱体起点。阶段标签之间的连续位置不自动表示整数评分。

percent bar 的数值轴使用归一化坐标，domain 若提供必须是 `[0, 100]`；原始数量不使用百分比 domain 校验。其 referenceLines/bands/ticks 同样以百分比为单位。负数归一化不在本版支持范围。

对于 `bar`，新增字段只适用于数值轴；对于 `line`，初版只允许数值坐标轴使用 domain/ticks。日期轴和分类轴的范围规则不混用数值规则。

### 3.4 参考线、阶段区间与定位标记

拟在 `line / bar / range` 数据集上加入可选 `annotations` 对象：

| 子集合 | 核心字段 | 用途 |
| --- | --- | --- |
| `referenceLines[]` | `key, axis, value, role, label?` | 阈值、目标、比较基准 |
| `bands[]` | `key, axis, from, to, role, label?` | 生命周期阶段、预测区间、评分等级范围 |
| `markers[]` | `key, target, role, label?, description?` | 当前技术位置、重点观测 |

拟定枚举：

- reference line role：`threshold | target | baseline`。
- band role：`stage | forecast | assessment`。
- marker role：`current_position | highlight`。
- axis：`x | y`，指实际视觉坐标轴，与横向条形图的轴定义一致。

初版参考线与 bands 的坐标为 number，只用于数值轴；`from < to`。同轴同角色的 bands 不得有内部重叠，可以共享边界。共享边界按左闭右开归属，最后一个区间包含右端点；不自动要求区间覆盖整条轴。它们不是统计置信带。各子集合可以省略；annotation key 在同一图表的三个子集合之间也必须唯一。

marker target 按图型选择以下三种结构之一：

- `{"seriesKey": "...", "pointKey": "..."}`：用于 line，目标点必须提供 key。
- `{"seriesKey": "...", "pointKey": "...", "anchor": "low | high | center"}`：用于 range，anchor 必须选其中一个值；center 必须实际存在，不能自动取中点。
- `{"seriesKey": "...", "categoryKey": "..."}`：用于 bar，必须解析到该序列中的分类观测。

定位引用采用数据坐标，不存储画布像素。标记、预测身份和阈值是业务语义；其颜色、虚实线和说明框布局由渲染器实现。

bar marker 标在该观测对应柱段的外端；stacked 时为按 series 数组顺序累计后的外端，percent 时为归一化后的外端。不能将原始段值误当成最终坐标。同一图表最多声明一个 current_position；多主体独立定位初版拆成多个图。

percent 某分类合计为零时没有数值位置，不能对该分类设置 marker；应使用图外说明，不将其定位到 0%。同轴同角色的 bands 按 from 排序进行重叠和边界归属校验，保留输入数组顺序用于往返；只有共享边界才需要右侧优先，不把不相邻区间之间的空白自动归给任何阶段。

referenceLines 的 value、bands 的 from/to、markers 的 target 都必须显式提供。禁止混用 pointKey 与 categoryKey。带 annotation 引用的 line 序列中，所有已提供的点 key 必须唯一；带引用的 bar 序列中 categoryKey 必须唯一，解析有歧义时报错，不取第一项。

启用数值轴扩展时，关联轴必须显式声明 `valueType = number | year`，坐标以 JSON number 提供。字符串 `"2025"` 不隐式转换成数字；未启用扩展的旧 line 坐标仍允许原有字符串形式。

初版不把这些字段直接推广到 pie、流程图或 matrix_bubble；其坐标语义需要独立设计。

## 4. 新增 `timeline`

用于有真实日期或日期区间的企业事件，不表示任务完成百分比。

| 字段 | 必须 | 说明 |
| --- | --- | --- |
| `chartType` | 是 | `timeline` |
| `events` | 是 | 非空事件数组 |
| `asOf` | 否 | 报告基准日期，格式 YYYY-MM-DD |
| `spacing` | 否 | `ordinal`（默认）或 `temporal`；节点间距表示顺序还是实际时间 |

事件字段：`key`、`start`、`label` 必须；`end`、`description`、`eventType`、`status` 可选。start/end 使用 `{value, precision}`，precision 为 `year | month | day`，value 分别为 YYYY、YYYY-MM、YYYY-MM-DD；eventType 是可选业务分类字符串，不决定布局。status 为 `occurred | ongoing | planned | cancelled`，省略表示未声明，不根据日期自动推断事件已经发生。

```json
{
  "id": "chart-milestones",
  "chartType": "timeline",
  "asOf": "2026-09-01",
  "events": [
    {"key": "founded", "start": {"value": "2020", "precision": "year"}, "label": {"zh": "企业成立"}},
    {"key": "pilot", "start": {"value": "2025-03", "precision": "month"}, "end": {"value": "2025-06", "precision": "month"}, "label": {"zh": "试点验证"}}
  ]
}
```

规则：日期必须合法；同一事件的 start/end 精度一致且 end 不早于 start。事件按时间排列，同期事件保持数组顺序；不同精度事件按其日期期间的起点排序，但不得展示成虚构的精确日期。允许多个事件发生在同一天。渲染器必须保留精度信息。

排序是渲染视图规则，读写往返保留 events 原始顺序。年份范围为 0001–9999，不支持时区和时刻。end 表示最后一个包含的日期期间；省略 end 不表示持续至今，持续状态由 status 声明。planned 不自动转为 occurred。

asOf 是本图评估时点，不从 meta 的其他日期字段隐式继承。若声明 occurred 的事件开始期间整体晚于 asOf，校验报错；ongoing 的开始期间也不能整体晚于 asOf、结束期间不能整体早于 asOf。日期精度覆盖 asOf 时不能凭较低精度断言矛盾。asOf 不截断时间轴，未来计划仍可展示，但必须与已发生事件区分。

occurred 表示事件已发生、区间事件已结束，因此若 end 期间整体晚于 asOf 也报错；尚在持续的事件应声明 ongoing。planned 的日期早于 asOf 不会自动变成 occurred，可给出“计划日期已过、状态未更新”的 warning。没有 asOf 时只校验日期结构和区间顺序，不以机器当前日期改变结果。

ordinal 模式适合报告的里程碑节点，间距不表示历时；日期必须可见。temporal 模式按日期期间起点计算位置，节点的日期精度必须可见，区间事件应表达持续范围。两种模式不得静默互换，避免把等距事件误读为等长时间。asOf 若提供必须有可见的基准日期标记或说明，但不自动添加业务事件；它若落在全部事件之外也不得被裁掉。

## 5. 新增 `stage_progress`

用于有序阶段和证据支持的当前位置，不要求阶段有日期。

字段：`stages` 为非空有序数组；每项包含 `key`、`label`，可选 `description`、`status`。status 为 `not_started | in_progress | completed | blocked | skipped`，省略表示未声明。`currentStageKey` 为可选的当前业务定位；它是强调位置，不替代阶段状态。

```json
{
  "id": "chart-development",
  "chartType": "stage_progress",
  "stages": [
    {"key": "research", "label": {"zh": "研究"}, "status": "completed"},
    {"key": "prototype", "label": {"zh": "原型"}, "status": "in_progress"},
    {"key": "validation", "label": {"zh": "验证"}}
  ],
  "currentStageKey": "prototype"
}
```

规则：key 唯一，currentStageKey 必须解析；当前定位可指向已完成、进行中或受阻阶段，也可指向状态未声明的阶段，但不能指向 not_started 或 skipped。例如“原型已完成、企业目前处于原型阶段”是合法组合，不能强迫作者改成“原型正在进行”。

省略 currentStageKey 表示没有声明当前位置，不默认选第一个或最后完成的阶段。初版允许非连续完成及多个进行中的阶段，不自动推导其他状态，也不按阶段数计算完成百分比。状态与位置分开后不再提供 completedStageKeys，避免双重状态来源。

## 6. 新增 `flow`

用于输入、处理、输出的有向关系。初版以有向无环流程为范围；不包含流量宽度、桑基流量守恒或循环工作流执行语义。

字段：`nodes` 为非空数组；`edges` 为必须存在、可以为空的数组；`groups` 为可选数组。

- node：`key, label` 必须；`description, role, groupKey` 可选。role 为 `input | process | output`。
- edge：`key, sourceKey, targetKey` 必须；`label` 可选。
- group：`key, label` 必须；`description` 可选。初版只支持单层分组，每节点最多归属一组。

```json
{
  "id": "chart-analysis-flow",
  "chartType": "flow",
  "nodes": [
    {"key": "input", "role": "input", "label": {"zh": "分析数据"}},
    {"key": "model", "role": "process", "label": {"zh": "评估模型"}},
    {"key": "output", "role": "output", "label": {"zh": "评估结果"}}
  ],
  "edges": [
    {"key": "input-model", "sourceKey": "input", "targetKey": "model"},
    {"key": "model-output", "sourceKey": "model", "targetKey": "output"}
  ]
}
```

节点、边、分组各自 key 唯一；端点和 groupKey 必须解析；禁止自连接、循环和重复 source/target 对。孤立节点允许存在。分层布局、箭头形状、节点坐标由渲染器决定，连接关系必须被保留。

edges 只连接节点，不能把 groupKey 当作端点；数组顺序为同层节点的稳定展示顺序提供提示，不代替拓扑关系。role 是语义标签，不产生隐含边。`flow` 不运行条件表达式，Yes/No 分支可以通过明确节点和 edge.label 表达；不能从标签文本执行逻辑。空分组报告 warning，不因此制造节点。

## 7. 新增 `funnel`

首版用于有序市场包含层级。必须字段 `relationship = containment` 显式声明包含关系；本版不提供 conversion，不将市场规模比例自动解释为销售转化率。转化漏斗需另行明确统计口径和重复计数规则后再扩展。

字段：`stages` 为非空数组；`valueUnit` 可选。每个 stage 必须有 `key, label`，可选 `description, value`；省略 value 表示规模未知，不使用零或占位字符串伪装数值。

```json
{
  "id": "chart-market-hierarchy",
  "chartType": "funnel",
  "relationship": "containment",
  "valueUnit": "GBP",
  "stages": [
    {"key": "tam", "label": {"en": "TAM"}, "value": 100000000},
    {"key": "sam", "label": {"en": "SAM"}, "value": 20000000},
    {"key": "som", "label": {"en": "SOM"}, "value": 2000000}
  ]
}
```

数组顺序由外到内，stage key 唯一；数值非负且单位一致；任意已知内层值不得超过任意已知外层值，不能因为中间层未知而跳过该检查。只在相邻两层数值已知且分母大于零时计算包含比例；未知值情况下保留层级并显示未提供，不伪造按比例面积。

各层必须来自可比较的统计时点、范围与口径；校验器只能验证数值关系，不能证明真实集合包含，作者需在 description 中解释范围。默认梯形宽度只表示层级，不承诺面积／宽度与金额成比例；显示数值与单位即可。渲染器若采用比例编码，必须明确编码方式，不用装饰性尺寸暗示额外数量关系。

## 8. 新增 `range`

用于分类项下的上下限区间。区间可以是估值范围或其他业务范围，不默认表示统计置信区间。

| 字段 | 必须 | 说明 |
| --- | --- | --- |
| `categories` | 是 | 非空，复用 ChartCategory |
| `series` | 是 | 非空区间序列数组 |
| `orientation` | 否 | `horizontal`（默认）或 `vertical` |
| `rangeDisplay` | 否 | 首版仅 `band`（默认）；其他值不在本版合同内 |
| `valueUnit` | 否 | 同一数值轴的默认单位 |
| `xAxis / yAxis` | 否 | 复用 ChartAxis |
| `annotations` | 否 | 复用参考线、区间和定位标记 |

series 必须含 `key, points`，points 非空；可选 `label, description, dataRole`。point 必须含 `key, categoryKey, low, high`；可选 `center, label, description, dataRole`。同一序列的 point key 和 categoryKey 各自唯一。

```json
{
  "id": "chart-value-ranges",
  "chartType": "range",
  "orientation": "horizontal",
  "rangeDisplay": "band",
  "valueUnit": "GBP million",
  "categories": [{"key": "method-a", "label": {"zh": "方法 A"}}],
  "series": [{"key": "valuation", "points": [{"key": "a", "categoryKey": "method-a", "low": 10, "high": 15}]}]
}
```

规则：`low <= high`；若提供 center 则 `low <= center <= high`；不自动取中点冒充中心估计。band 中提供 center 时必须展示中心标记，不能忽略作者给出的中心信息。端点相等表示退化区间，不能丢弃该点。横向时数值轴为 x，纵向时为 y；多序列同分类并列，不堆叠区间。不同单位的指标拆成不同图，初版不引入双轴。

categories 与 series 的 key 分别唯一，categoryKey 必须解析；categories 数组确定展示顺序。允许某序列缺少部分分类，缺少的区间留空，不产生 `[0, 0]`，已有区间不得重排到其他分类。low/high 为必须的数值，不支持单侧无界区间。区间含义由 series.label/description 解释，初版不承诺机器可读的置信水平或分位数语义。

`point_interval` 和中心点连线是后续候选，不纳入首版枚举、示例或“已支持”清单；如果需求恢复，需补充规则后再纳入，而非发布半实现字段。

## 9. 增强 `line`

沿用 `series[].points[].xValue / yValue / label`，新增共享的 dataRole、axis domain/ticks 和 annotations。

- 历史／预测趋势：用不同 dataRole 的序列表达，可在数值年份轴上增加 forecast band。
- 生命周期 S 曲线：提供 dataBasis=illustrative 的曲线采样点、stage bands 和 current_position marker。
- 技术成熟度曲线：同样提供采样点、命名阶段和当前定位；不从数据自动声称属于官方评估。
- 专利申请量与申请人数量轨迹：维持 v1.3 的数值坐标和年份标签，按输入数组顺序连接，不按 xValue 重新排序。

曲线由作者端提供采样点；初版不内置 S 曲线或技术成熟度曲线公式，不用一个名称让不同渲染器各自生成不同坐标。平滑是渲染细节，但不得改变点序、制造与原始数据不符的极值，或改变当前定位的含义。

下面是可附加到一个 line 数据集上的字段片段：

```json
{
  "annotations": {
    "bands": [
      {"key": "growth", "axis": "x", "from": 1, "to": 2, "role": "stage", "label": {"zh": "成长阶段"}}
    ],
    "markers": [
      {"key": "current", "target": {"seriesKey": "lifecycle", "pointKey": "position"}, "role": "current_position", "label": {"zh": "当前定位"}}
    ]
  }
}
```

该片段要求宿主图中存在 lifecycle 序列及 position 点，且 xAxis.valueType 为 number；不是可单独使用的完整图表。完整示例见第 15.2 节。

## 10. 增强 `bar`

保留 `orientation` 与 `barMode = grouped | stacked`，补充共享的 dataRole、量表与 annotations。

### 10.1 TRL 与其他有界评分

每个工作流仍是一项 category，分数仍为 value；通过数值轴 domain 表达合法量表范围，referenceLines 表达阈值。量表不改变数值本身；门槛未达到不能因渲染器忽略参考线而表现为已达到。

### 10.2 风险筛查占比

使用两个序列表达已触发和未触发数量。拟新增 `normalization = none | percent`，默认 none；percent 仅允许非负 stacked 数据，每个分类按其序列合计归一化到 100%。原始数量仍保留，渲染器可显示分子／分母。

percent 模式中，valueUnit 继续表示原始观测单位（例如 count）；数值轴 unit 若提供必须为 percent，省略则推导为 percent。标签应区分原始数量与归一化比例；参考线 50 表示 50%，不是 50 项。归一化只发生于渲染计算，保存时不得把原始数量替换为百分比。

合计为零表示没有可计算的占比，必须显示无数据状态，不输出 0/0 或误示全部通过。缺失某序列的分类观测不自动补零；percent 模式要求每个序列都显式提供每个分类的观测。

### 10.3 敏感性龙卷风图

用两个序列表达两种情景相对基准的变化值，单位是变化量，而非企业绝对估值。序列 label 应清楚解释情景，分类 label/description 描述扰动假设。

stacked 的正数从零向正方向累加，负数从零向负方向独立累加；不得将正负值相抵后再画一个条。横向 stacked 能表达当前报告的正负敏感性比较，category 数组确定排列顺序。

初版不自动生成敏感性情景、计算扰动或重新排序，也不把任意两个同号情景强制包装成对称龙卷风。未来若需自动计算、同号情景的专门布局或机器可解析的扰动参数，应独立评审 sensitivity 模型。

## 11. 增强 `doughnut`

拟增加可选 `centerContent`：`primary` 为必须的语言对象，`secondary` 为可选语言对象。

```json
{
  "centerContent": {
    "primary": {"zh": "10–15 百万英镑", "en": "GBP 10–15m"},
    "secondary": {"zh": "估值区间", "en": "Valuation range"}
  }
}
```

这是圆环数据集的可选字段片段。它是显式的展示文本，不参与 slices/total 计算，也不要求与圆环总量相同。中心文字若在不同正文位置需要变化，初版使用不同数据集，不增加正文实例级覆盖规则。字体缩放和换行由渲染器决定，不能静默截掉关键数值。

## 12. 组合展示与兼容

### 12.1 组合展示

沿用 grid 表格的文本、图片和 chart 单元格能力组合团队画像、双图面板、指标摘要和风险说明。重新核对编号实现后，单靠 table + 相邻 figure_caption 不能使一个 table 正式成为 figure，也不能把四张 chart 自动归到一个图号；因此本版增加最小组合实例。

新增正文块：

```json
{
  "_type": "figure",
  "id": "fig-comparison-panel",
  "layoutRef": "layout-comparison-panel",
  "keepTogether": true
}
```

- id 必须，anchor 可选并沿用省略时回退 id 的规则；layoutRef 必须指向 `datasets.tables` 中的 grid 数据集，不能指向 record 表格。
- keepTogether 为可选 boolean，默认 true；表示尽量同页排布。若整个组合无法放入一页，渲染器应分页并保留同一个 figure 身份、提供续图标识，不得缩小到不可读或丢弃分图。
- figure 仅允许出现在章节的 content.blocks，不允许进入 grid 单元格、callout、脚注或另一个 figure。它没有 children 数组，不支持任意递归容器。
- 内部复用 grid 单元格的 block/image/chart、列宽和跨行跨列能力，不添加嵌套 table。标题、指标卡、分图标签和说明用普通文本块表达。
- 整个组合分配一个 figure 号；引用使用 `xref.targetType=figure` 指向该正文实例 id，不能指向 layoutRef 作为图号。
- 供 figure 使用的 grid 内，chart/image 实例不得声明 id 或 anchor，避免多次复用时出现全局实例 ID 冲突；子图不单独编号、不提供子图级 xref。其数据集 id 仍照常可解析。
- 同一个 grid 布局可被多个 figure 引用，各 figure 有各自的实例 id 和编号；读取时不复制数据集。相邻 figure_caption 沿用现有说明方式，正文图号由编号器提供，不能靠手写数字维护。
- 该 grid 不作为独立 table 分配编号；只有独立正文 table 实例才进入 table 计数。团队画像若标题为 Table，继续使用 table，不强制包装成 figure。

同一组合中的 mini doughnut 若需要一致的能力分类配色，数据生成端使用一致的 slice.key，渲染器模板按该 key 使用一致映射；保留既有 colorHint 的可选提示，不新增全局调色板协议。布局边框、卡片底色、字体和共享图例的具体位置仍由模板负责。共享图例只能在各图分类含义一致时展示，不能仅因 key 同名合并不同含义。

figure 的新增需要同步 BlockElement、正文解析、resolver、编号器、编辑器选择／复制／删除和渲染器；现有代码尚无此能力。必须检查布局中 chartRef/imageRef 的间接依赖，不能只检查正文直接 chartRef。不得用静态截图作为组合图实现验收的替代。

组合实例的 caption 关联采用最小相邻约定：同一 content.blocks 中紧接 figure 的连续 `style=figure_caption` 文本块，按输入顺序作为它的说明；遇到其他块或 content 结束即终止，不跨 content/section 搜索，也不从文字数字猜测归属。没有紧邻 caption 时组合仍合法，模板可只显示图号。caption 的文字仍独立保存，编号器不改写其 span 内容。新约定仅针对新增 figure，不追溯改变旧 chart/image 的 caption 处理。

编号只按正文阅读顺序遍历实例，不能按 registry 顺序分配；figure 与普通 chart/image 共用 figure 计数，不给 grid 或数据集分配正文图号。复制或移动 figure 时一并处理紧邻 caption；保留布局资源共享关系，除非显式选择独立副本。删除一个实例不隐式删除仍被其他实例使用的资源。

### 12.2 版本与完整呈现

- 使用本次新增字段或图型的文档声明 `report.v1.4`。
- 升级后的 SDK 和渲染器应继续支持既有 v1.3 文档，不重解释旧字段。
- v1.4 文档不保证可交由只认识 v1.3 的渲染器消费。
- 本次目标是同步升级后完整呈现，不主动将新图转换成旧图或图片。
- 未知版本遵循现有清晰报错原则；正式报告中缺少所需图型或关键业务语义能力时，不允许静默丢图或忽略关键语义。
- 预览环境可以显示明确的未支持占位提示，并保留图题和诊断；不能据此视为正式报告成功生成。
- 本草稿不新增备用图片 fallback 字段。运行前能力检查由消费端集成完成，首版不引入文档级能力协商协议。

上述正式输出约束是对 v1.4 消费端的拟议要求，不表示现有渲染器已经实现。发布时需明确它与 v1.3“未知图型可忽略”的差异。

v1.3 还允许不支持 stacked 的渲染器按 grouped 回退；v1.4 的正式输出要求明确覆盖该规则。对于 percent、正负敏感性等依赖堆叠语义的图，转换为 grouped 不算正确支持。未知扩展字段仍可按既有规则处理，不能把“忽略未知扩展”用于忽略 v1.4 已定义且实际使用的字段。

生成端校验、编辑器保存和正式输出是三种不同操作：编辑器可保留尚未识别的数据并给出提示，正式输出则检查实际被引用的图表所需能力。未引用的未知 registry 项不应单凭其存在阻止输出。对已知图型的非法结构始终报校验错误，不用“不支持该图”掩盖数据错误。

版本检查应采用明确的支持版本集合，不能按字符串大小比较 `report.v1.3` 与 `report.v1.4`。SDK 不得在保存旧文档时自动改 schemaVersion；调用新增 helper 构建新字段时，应要求或明确设置目标 v1.4，不能把新字段装入仍声称 v1.3 的输出。

本节用于实现核对，不引入额外字段。`—` 表示该图型没有此正式字段，不应因为 Python 共用基类而意外接受。

| 能力 | line | bar | range | 其他图型 |
| --- | --- | --- | --- | --- |
| dataBasis | 图表级 | 图表级 | 图表级 | — |
| dataRole | 序列、points | 序列、data | 序列、points | — |

| --- | --- |
| timeline.spacing | ordinal |
| range.orientation / rangeDisplay | horizontal / band |

| bar.normalization | none，不改变输入值 |

## 22. 解析、引用与错误分层

### 22.1 已知图型不能绕过校验

根据 schemaVersion 和 chartType 先选择明确模型，再执行结构和语义校验。v1.4 中已知类型缺字段、端点逆序或枚举错误必须失败，不能落入 GenericChartDataset。未知 chartType 可作为未解释的数据保存，不表示能正式输出。

已有字段在不适用图型上出现也应诊断，例如 line.normalization 或 pie.centerContent；不能把拼错位置的正式字段当作成功启用的功能。编辑器保留未知扩展不等于宣布该功能有效。

### 22.2 引用与依赖

分别维护全局 id/anchor 索引和图表内部 key 索引；局部 key 不参与全局冲突检测。figure 的依赖链为：

`正文 figure.layoutRef → grid 数据集 → 单元格 chartRef/imageRef → 图表／图片资源`

同一资源被两条路径使用只登记一次定义，不误报重复 ID；每一条使用路径都保留，便于报告哪些图受影响。能力检查遍历所有实际输出的正文对象，包括普通 table 中的图表，而不只遍历 figure。

组合布局中的 xref 仍可以指向正文外其他合法对象；资源共享不允许校验器跳过文本中的引用。重命名 layout 数据集时同时更新 figure.layoutRef 和普通 tableRef；重命名图表时更新所有 grid 与正文 chartRef，不修改局部 pointKey。资源删除前显示仍存的引用，不自动级联删除报告内容。

### 22.3 可执行的错误类别

下列 code 是拟议的稳定诊断标识；severity 在结构/语义校验与输出阶段分开判断。

| code | 场景 | 结果 |
| --- | --- | --- |
| `chart.required_field` | 已知图型缺主体字段 | 结构错误 |
| `chart.invalid_value` | 非法数值、枚举、日期或范围 | 结构／语义错误 |
| `chart.duplicate_key` | 指定局部范围内重复 key | 语义错误 |
| `chart.unresolved_target` | 注释引用、分类或 flow 端点不存在 | 语义错误 |
| `chart.axis_mismatch` | 数值标记落在分类轴、字符串数值混用 | 语义错误 |
| `chart.undefined_position` | 零分母 percent 上设置 marker | 语义错误 |
| `figure.invalid_layout_ref` | 缺少 grid 或误引用 record | 语义错误 |
| `figure.child_instance_identity` | figure 使用的 grid 子图含 id/anchor | 语义错误，不能靠忽略 id 修复 |
| `render.unsupported_feature` | 被引用内容所需能力未实现 | 预览占位；正式输出失败 |
| `timeline.overdue_plan` | 明确基准日前的计划未更新状态 | warning，不改写数据 |

诊断最少包含 code、severity、path、message；按上下文附 chartId、figureId 和 usagePath。共享 grid 出错时 path 指向唯一资源定义，usagePath 指向受影响实例；不能把资源复制成多份错误定义。具体载体应沿用当前 ValidationReport／EditorIssue，保持现有字段兼容。

### 22.4 三层验收不能互相替代

1. JSON 语法与数据合同：类型、字段、枚举、局部约束。
2. 文档整体语义：版本、引用、编号、数据性质、间接依赖与复用。
3. 渲染输出：全部使用的能力、可读性、图例、caption、分页和目标图型效果。

本轮只验证草稿示例的前两层中可直接检查的部分，未实现通用 v1.4 校验器，也未完成第三层。
